# AI 运营工作空间设计说明

## 1. 产品定位

本产品是面向外卖竞争态势运营的一体化 **AI Operations Workspace**，而非传统后台管理系统。

核心用户与首页优先级随身份自适应：

- 一线城市运营：上传订单截图、确认商家上下文、处理 AI 发现的异常。
- 城市负责人 / BD：聚焦负责范围内的商家风险、跟进行动与改善结果。
- 总部管理层：判断城市经营健康度、组织性风险与需介入的事项。

核心工作流为：**结论 → 原因 → 行动 → 证据**。AI 先给出运营判断，用户可在同一上下文中查看订单字段、趋势与商家证据并采取行动。

## 2. 体验策略

### 2.1 工作空间，而不是 Dashboard

首页命名为“今日运营”。它首先回答“今天发生了什么、为什么重要、该做什么”，而非罗列图表或功能模块。

空间由三部分组成：

1. 工作空间轨道：稳定路径、收藏、最近访问、AI 推荐入口。
2. 主运营画布：承载当前任务或判断；首页、上传、洞察和商家页均只服务一个主要意图。
3. AI 协作面：读取当前上下文、解释结论、生成行动建议；可收起。

### 2.2 双层 AI

- 首页顶部的 AI 指挥摘要：一句全局判断与三个可执行动作。
- 右侧常驻 AI 协作面：支持追问、解释证据、生成 BD 跟进建议。

AI 的表达应具体、可追溯、克制，不模拟冗长逐字输出。

### 2.3 视觉方向

默认采用“暗色专注舱”：低饱和蓝黑与石墨灰降低环境噪声，关键结论、行动与风险才获得亮度和颜色。浅色主题作为同一系统的可选阅读 / 处理模式。

## 3. Design System

### 3.1 表面层级

| 层级 | 用途 |
|---|---|
| Canvas | 整页环境底色与极弱径向环境光 |
| Workspace | 主工作承载面 |
| Focus Surface | AI 简报、风险任务、关键结论 |
| Action Surface | 可立即执行的内容 |
| Overlay | 命令面板、搜索、抽屉 |

以明度、透明度、轻模糊和阴影建立层级，避免密集边框与大面积实心卡片。

### 3.2 色彩

| 语义 | 深色 | 浅色 |
|---|---|---|
| 环境底色 | `#0A0E16` | `#F5F6F8` |
| 主工作面 | `#111927` | `#FFFFFF` |
| 主文字 | `#F3F6FB` | `#172033` |
| 次级文字 | `#A7B3C6` | `#6E7A8D` |
| AI / 主行动 | `#7899FF` | `#356AF3` |
| AI 辅助光 | `#A88CFF` | `#7759EF` |
| 正向 | `#42C89A` | `#078B68` |
| 预警 | `#F2B94B` | `#B77900` |
| 风险 | `#F47E72` | `#CB5047` |

渐变仅用于 AI 环境光，透明度不高于 18%，面积不超过单个表面的 25%。单屏高饱和色不超过三种。

### 3.3 字体

- 中文：PingFang SC；英文与数字：Inter。
- 标题：32/40，650–700。
- 区块标题：20/28，600。
- 卡片标题：14/20，600。
- 主指标：40/44，680；常规指标：24/30，650。
- 正文：14/22；元信息：12/18；标签：10/14，700，字距 0.12em。
- 金额、日期和指标启用等宽数字特性。

### 3.4 间距、网格与形状

间距基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80`。

- 控件内部：8–12；卡片内部：16–24；模块间：24–32；页面主要段落：40–64。
- PC：72px 轨道、12 列流式画布、320–360px AI 协作面、32px 页面外边距（大屏 48px）。
- 移动端：4 列网格、16px 页面边距、12px 卡片间距。
- 圆角：10px 小控件、14px 标准交互面、18px 信息表面、22–24px 重点表面与抽屉。

### 3.5 阴影与玻璃

- 静态表面基本无阴影。
- Hover：`0 10px 28px rgba(0,0,0,.16)`。
- Overlay：`0 24px 80px rgba(0,0,0,.32)`。
- Glassmorphism 仅用于悬浮导航、AI 协作面和 Overlay；普通数据卡不用玻璃效果。

## 4. 首页：今日运营

首页采用复合型指挥摘要：

1. 时间、范围与角色上下文。
2. AI 一句全局判断与影响解释。
3. 三个行动入口：查看重点商家、生成 BD 跟进建议、上传订单截图。
4. 信号面：今日运营健康度、重点异常、待处理动作、城市状态。

“今日运营健康度”不做孤立仪表盘，必须附带变化驱动与 AI 解释。异常按可处理运营对象呈现：商家 / 城市 / BD 上下文、风险、订单证据、AI 判断与下一步动作。城市状态采用可扫读状态列表，不使用密集排名表。

## 5. 导航

默认工作空间轨道提供六个稳定入口：今日运营、工作、洞察、商家、AI、我的。

展开后显示固定空间、收藏、最近访问和 AI 推荐。选中状态由侧边能量光、亮度提升和轻微玻璃表面表达，避免传统大色块菜单。

Command Palette（`⌘K / Ctrl K`）用于搜索商家 / BD / 城市、跳转空间、执行上传与导出动作，以及直接调用 AI 指令。

## 6. 卡片

每张卡片是一个运营判断单元，按需由以下层构成：

1. Context：城市、商家、BD、时间或来源。
2. Signal：健康度、变化、风险等级或待办数量。
3. Meaning：AI 对“为什么值得关注”的一句解释。
4. Evidence：订单字段变化、趋势、截图或对比数据。
5. Action：一个主动作与一个次动作。

核心类型为运营信号卡、异常对象卡与进展卡。风险色仅用于标签、边缘光或关键数字；完成状态降低饱和度，不抢占当前任务。

## 7. 动效

- 页面：淡入、上移 8px，180–220ms。
- 首屏：按重要度依次出现，间隔 35–50ms；AI 摘要先于证据出现。
- Hover：上移 2px，140ms；点击压缩至 0.985，80ms。
- 数字更新：240ms，并使用等宽数字。
- AI：读取证据 → 识别差异 → 形成建议；不使用冗长逐字生成。
- 支持“减少动态效果”。

## 8. 平台适配

### PC

PC 用于深度判断：三域空间、局部下钻、截图与证据对照、可收起 AI 协作面和全局命令面板。

### Mobile

移动端为 AI 办公 App，不缩放 PC。底部导航为首页、工作、AI、消息、我的。首屏仅保留今日结论、最重要异常、上传 / 待办两个快捷动作与 AI 推荐。详情通过底部 Sheet 展开；上传识别使用全屏沉浸流程；AI 变为可上拉协作 Sheet。

## 9. 设计成功标准

- 用户打开后先看到判断与行动，而不是数据墙。
- 一线运营可在少量步骤中完成上传、确认与跟进。
- 管理者可从城市到 BD 到商家保持同一上下文地下钻。
- AI 的建议能回到订单证据与字段，而不是黑箱结论。
- 深色主题长期使用不疲劳，且不呈现传统 ERP / 后台气质。
