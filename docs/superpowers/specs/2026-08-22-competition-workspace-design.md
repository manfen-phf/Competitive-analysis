# 外卖竞争分析工作台：完整版设计说明

## 1. 目标与范围

本版本只服务一条业务闭环：订单截图采集、AI 识别、结构化入库、竞争价格力分析、数据管理与导出。

本版本不包含任务系统、聊天系统、泛化 AI 助手、复杂审批流或与采集分析无关的页面。

核心角色：

- **BD**：选择本人负责商家，输入原价配送费，上传美团和 B 家订单截图，校对识别结果并确认。
- **管理员**：维护城市 / 商家 / BD 主数据，查看采集质量、查询所有订单数据、分析平台差异、导出数据。

## 1.1 访问控制

V1 设三类正式账号，不扩展为复杂审批或团队权限体系：

- **超级管理员账号（2 人）**：可进入全部页面；可导入商家主数据、管理账号、查看与修改全量数据、查看原图、确认结果、导出全量 Excel。
- **城市管理员账号（每城 1 人，共 8 人）**：可查看 8 个城市的概览、分析与数据明细；仅能修改、确认和导出自己所属城市的数据；没有主数据导入、账号管理、跨城市修改或跨城市导出权限。
- **BD 账号**：使用“BD 姓名 + 独立初始口令”登录；只能进入首页、采集和分析；采集时只能选择自己负责的商家；分析页只能查看自己负责商家、城市范围内的汇总和明细，不可进入主数据或数据中心，不可导出数据。

未登录用户访问受限页面时，必须被引导到登录页；直接输入 URL 也不能绕过页面权限。API 同样依据账号角色、城市归属和 BD 商家关联限制返回范围，不能仅依赖前端隐藏菜单。

## 2. 页面结构

左侧固定导航仅保留：

1. 概览 `/`
2. 采集 `/upload`
3. 分析 `/dashboard`
4. 数据 `/health`（页面标题固定使用“数据中心”）
5. 主数据 `/admin/import`

所有页面共享工作台外壳：左侧导航、顶部上下文、页面标题与返回概览入口。手机端使用底部导航：概览、采集、分析、数据、我的；筛选通过底部抽屉打开。

导航按角色收敛：超级管理员可见全部五项；城市管理员可见概览、采集、分析、数据；BD 仅可见概览、采集、分析。BD 手机端同样不显示“数据”入口，个人页只展示账号与当前负责商家范围。

## 3. 视觉系统

### 色彩语义

- 画布：深蓝黑 `#070B16`
- 面板：深海军蓝 `#0D1527`，带轻微层次，不使用廉价大面积渐变
- 边界：`#213453`
- 主操作：蓝色 `#5C8DFF`
- 美团：黄色 `#FFC300`
- B家：蓝色 `#2F7DFF`
- 正向 / 改善：绿色 `#52D4A7`
- 风险 / 下降：红色 `#FF748A`
- 辅助强调：紫色 `#9D79FF`，仅用于非平台语义（例如当前选中状态）

平台颜色只用来辨认平台；绿和红只表达结果好坏，不能混用。

### 排版与控件

- 使用 8px 间距网格。
- 标准输入框、选择器、按钮高度为 40px。
- 卡片圆角 16px；紧凑行、标签、弹层控件圆角 10px；胶囊状态 999px。
- 图标统一 18px，导航图标 20px；图标与文字保持同一基线。
- 页面标题、字段标题、数值、说明文字使用明确的字号层级；数值使用等宽数字样式。
- 卡片、表格和筛选器只使用同一层级的边框与投影，避免每个区块看起来像独立产品。

## 4. 概览页

概览是入口页，不代替分析页。

首屏提供：

- 今日已采集商家数与订单数
- 待确认数量
- 识别失败数量
- 快速入口：继续采集、查看待确认、进入竞争分析
- 最近采集动态
- 需要关注的异常商家

点击任一状态将进入对应的采集、数据中心或分析页。概览不展示复杂图表。

## 5. 采集与确认流程

采集页是一张明确的任务单，流程固定为：

`选择商家 → 输入原价配送费 → 上传美团截图 + B家截图 → AI 识别 → 双栏校对 → 确认入库`

### 采集页信息

- 当前城市、商家名称、商家 ID、BD 名称。
- 原价配送费为 BD 输入项，作为同一采集任务中两个平台订单的计算条件。
- 两个独立上传槽：美团以黄标识、B家以蓝标识。
- 每个上传槽拥有：空、上传中、已上传、识别中、识别成功、识别失败、重复上传等可见状态。
- 重复上传不静默失败：提示已有记录的商家、平台和采集时间。

### 校对字段

人工可修正的识别字段：

- 商品总价（必填）
- 打包费
- 商家活动款
- 其他活动
- 减配送费
- 平台红包抵扣金额
- 平台红包商家承担
- 结算金额
- 技术服务费
- 配送服务费

系统计算字段：

- 菜品原价 = 商品总价 - 打包费；若截图未显示打包费，则取商品总价
- 实付配送费 = max(原价配送费 - 减配送费, 0)
- 用户实付 = 菜品原价 + 原价配送费 - 商家活动款
- 实际费率 = (技术服务费 + 配送服务费) / 商品总价

订单号不是必填字段。系统计算值在校对页只读显示，并在源字段修改时实时刷新。

确认后才写入正式订单数据；识别失败和待确认结果必须保留并可在数据中心处理。

## 6. 分析页

分析页让管理者快速回答：哪个平台更有价格力、差异来自哪项指标、哪个商家值得优先跟进。

### 分析控制台

常驻筛选条件：

- 时间粒度：日 / 周 / 月 / 年
- 日期范围
- 城市
- BD
- 商家
- 重点指标

高级筛选收进弹层。用户每次筛选后显示可移除的条件标签。

不使用浏览器原生日期选择器。日期使用统一的产品内弹层：

- 日：双月日历
- 周：自然周，例如 `2026 W1 · 01/01–01/04`
- 月：月份网格
- 年：年份网格

### 内容顺序

1. 四个结论卡：有效订单、美团当前指标、B家当前指标、平台差异。
2. 当前指标趋势：固定以美团黄、B家蓝呈现，支持按当前时间粒度切换。
3. 指标对比矩阵：展示所有核心字段的美团均值、B家均值与差异。点击任意指标，KPI、趋势和排行同步更新。
4. 商家差异排行：按当前重点指标的绝对差异排序，支持进入商家详情 / 数据明细。

每个图表必须有加载、空数据与错误状态；趋势与矩阵均显示数值，不能只依赖颜色。

## 7. 数据中心

数据中心承担查、核、改、导出，不重复分析页的图表。

顶部数据质量摘要：已识别、待确认、识别失败、平均置信度。

订单明细默认按最新采集排序，可按日期、城市、BD、商家、平台、识别状态筛选。每条记录支持：

- 查看原图
- 查看识别字段
- 修改并重新确认
- 导出当前筛选结果为 Excel

数据中心与分析页共用筛选口径与字段名称。超级管理员可管理全量数据；城市管理员可查看所有城市数据，但编辑、确认和导出动作仅对其所属城市可用；BD 不显示入口，也不能通过直接 URL 或 API 请求访问管理员明细。

## 8. 组件边界

为避免继续在全局 CSS 中叠加样式，界面实现应收敛为：

- `WorkspaceShell`：导航、顶栏、移动端导航与页面容器。
- `PageHeader`：返回入口、标题、说明、页面级操作。
- `FilterDock`：筛选触发器、条件标签、桌面弹层和移动端抽屉。
- `MetricCard`：统一 KPI 卡片。
- `PlatformBadge` / `PlatformLegend`：平台色彩与标签。
- `DataState`：加载、空数据、失败状态。
- `ComparisonMatrix`、`TrendChart`、`MerchantRanking`：仅接收规范化分析数据。
- `OrderReviewForm`：上传后双平台字段校对与计算结果。
- `OrdersTable`：数据中心明细及操作入口。

页面只负责组合组件和请求数据，计算规则继续保留在现有业务层。

## 9. 数据与接口边界

本次界面收敛不改变既有识别字段、去重规则、入库含义或 API 返回的数据含义。账号角色、城市归属和商家-BD 关联是每个数据接口的授权条件。城市管理员的查询接口可返回全城市范围；修改、确认和导出接口必须从服务端验证目标记录的城市与其所属城市一致。

- 真实数据进入相同的采集、确认、分析和数据中心页面。
- 演示数据仅用于分析页无真实订单时的视觉与功能预览，必须明确标识，不能和正式记录混淆。
- 任何 API 错误都显示可理解的失败状态并保留用户已选择的筛选条件或填写内容。

## 10. 响应式与可访问性

- 桌面基准：1440px。
- 平板：768px，分析矩阵与趋势改为单列，筛选器保持可折叠。
- 手机：390px，底部导航；KPI 保持两列；筛选器在底部抽屉中按步骤选择；数据表转为摘要列表。
- 所有键盘可操作控件具有可见焦点；色彩不是唯一的信息传达方式；触控目标至少 40px。

## 11. 验收与测试

每个页面完成后执行：

1. 桌面、平板、手机宽度的视觉检查。
2. 浏览器控制台无新增错误。
3. 筛选条件联动、重置与空状态检查。
4. 上传、重复上传、识别成功、识别失败、字段修改、确认入库路径检查。
5. 管理员数据查询、原图查看、Excel 导出路径检查。
6. 自动化单元测试和生产构建。

## 12. 实施顺序

1. 建立统一工作台外壳、设计令牌和基础组件。
2. 完成采集 / 校对页的任务流与状态。
3. 完成分析控制台、趋势、矩阵、排行。
4. 完成数据中心与数据质量状态。
5. 完成概览入口页。
6. 做三端视觉 QA、交互 QA 和真实数据链路验收。
