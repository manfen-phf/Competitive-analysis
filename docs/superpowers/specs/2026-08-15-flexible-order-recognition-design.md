# 异构订单截图识别设计

## 目标

让美团和 B 家的不同订单详情截图都能保存：只要求识别到商品总价，其他未展示字段保留为空；原价配送费由 BD 在采集时填写。

## 统一数据口径

- `goodsTotal`：商品总价，唯一识别必填字段。
- `dishPrice`：商品总价减打包费；无打包费时等于商品总价。
- `merchantActivityAmount`：美团的“商家对顾客的活动补贴”或 B 家的“商家承担活动款”。
- `originalDeliveryFee`：BD 在本次采集时填写，适用于美团与 B 家两张图。
- `deliveryFeeReduction`：商家承担的减配送费。
- `platformRedPacketAmount` / `platformRedPacketMerchantShare`：平台红包抵扣与商家承担部分。
- `userPaidAmount`：由系统计算：商品总价 + 原价配送费 - 商家活动款。
- `merchantRate`：由系统计算：(技术服务费 + 配送服务费) / 商品总价。

除商品总价外，截图未显示的字段存储为 `null`，绝不写入假定的 0。订单号也允许为空，因为不同截图可能未包含订单信息。上传图片哈希仍全局唯一，是唯一的去重依据。

## 数据流

BD 选择商家后输入原价配送费，上传一张美团和一张 B 家订单图。系统把配送费写入采集任务并保存原图哈希。千问按上传平台识别图片，返回可空字段和必填商品总价；系统补算菜品原价、用户实付与实际费率。BD 可修改结果，确认时把两条平台订单的原始字段与计算字段正式写入 D1。

## 存储策略

保留现有 `ConfirmedOrder` 作为历史兼容表，不做破坏性删除。新增 V1 的灵活订单数据表，字段均可空（商品总价除外），并以 `uploadImageId` 唯一约束保证每张图一条正式订单。采集任务新增 `originalDeliveryFee`，以便两张图共享同一配送费口径。

## 失败处理

仅在商品总价无法识别、平台不匹配、图片重复、或千问不可用时标记识别失败。字段缺失不再导致失败；BD 可在确认页补齐或保留为空。计算字段只在所需输入齐全时产生值。

## 验收

1. 美团和 B 家测试截图都能触发识别，缺失字段不被拒绝。
2. 每张图的商品总价、打包费和活动款按截图语义映射。
3. 采集任务保存 BD 输入的原价配送费。
4. 确认页显示可空字段以及系统计算的用户实付、实际费率。
5. 同一文件再次上传被哈希去重。
6. D1 中保存两条正式订单记录，可区分空值与金额 0。
