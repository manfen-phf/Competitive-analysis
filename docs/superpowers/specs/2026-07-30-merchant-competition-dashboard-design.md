# 商家维度外卖竞争态势分析工具：第一版设计

## 目标与使用者

这是一个内部 Web 工具，用于比较同一商家在美团和 B家（产品内对饿了么的统一称呼）的竞争价格力。

- 一线城市运营人员：选择城市和商家后上传订单详情截图。
- 总部/管理层：按时间、城市、BD、商家查看价格构成、差异和排名。
- 主数据维护人：仅由产品负责人导入商家与 BD 主数据。

普通使用不需要登录。

## 主数据

商家主数据导入 Excel，至少包含：

- 商家 ID
- 商家名称
- 城市
- BD 姓名
- 生效开始日
- 生效结束日

商家 ID 是主键。一个商家可有多段 BD 归属记录，归属按上传日期匹配。导入前必须展示新增、更新、失效和错误预览；只有整份文件校验通过才原子生效。系统保留导入版本及变更记录。

普通访问没有账号体系；主数据导入入口通过独立管理员口令保护。

## 上传与识别

### 操作流程

1. 用户选择城市。
2. 用户在该城市范围内按商家 ID 或商家名称搜索并选择商家。
3. 用户上传单张或多张订单详情截图。
4. 系统从图片识别平台（美团或 B家）及所有必填金额字段。
5. 系统校验字段完整性、格式、金额关系和重复记录。
6. 成功的数据入库；失败图片不入库，仅展示失败原因。

一张截图只对应一个商家和一个平台。城市与商家由用户手动选择；BD 按商家归属及上传日期自动带出。报表日期采用上传时间，不采用图片中的下单或完成时间。

### 必填识别字段

- 菜品原价
- 餐盒费
- 平台红包
- 原价配送费
- 减配送费
- 实付配送费
- 商家结算金额
- 用户实付
- 其他活动
- 技术服务费
- 配送服务费
- 商家费率

任一字段缺失、置信度不足、平台不能识别或金额关系不合理，整张截图上传失败。不提供人工补录或编辑。商家费率同时通过技术服务费与计费基数进行合理性校验。系统以图片指纹和订单号双重去重。

## 时间口径

筛选器支持日、周、月、年及范围选择，采用双面板日历，不提供“最近 7 天”“本月”等快捷选择。

周按每年内自然周编号：1 月 1 日至该周周日为 W1，即使不足七天；随后每个周一至周日为一个完整周。例如 2026-01-01 至 2026-01-04 为 W1，2026-01-05 至 2026-01-11 为 W2。

## 竞争价格力看板

所有金额按商家、平台和筛选周期汇总后除以有效订单数，统一呈现为每单平均值。仅统计通过识别、校验和去重的记录，并在每项结果旁展示有效订单数。

### 全局筛选

- 日、周、月、年与日期范围
- 城市
- BD
- 商家

平台固定为美团与 B家，用于并列比较，无需手动切换。

### 主看板

- 核心概览：订单数、用户实付、平台红包、配送费、商家结算金额及平台差异。
- 价格构成对比：菜品原价、餐盒费、平台红包、其他活动、原价配送费、减配送费、实付配送费、技术服务费、配送服务费、商家费率。
- 商家排名：按用户实付差异或商家结算差异排序，标示哪个平台更有价格优势。
- 下钻：从城市或 BD 汇总进入商家明细。
- 明细追溯：显示成功截图的识别字段和原图，不可修改。

## 次级采集健康页面

采集健康不作为主看板核心，单独提供：有效截图数、失败数、重复数、商家覆盖率、按城市与 BD 的上传情况，以及可追溯的失败原因和原图。

## 技术方案

采用定制 Web 前端、服务端 API、关系型数据库、图片对象存储和多模态 AI 识别服务。数据层将主数据、导入版本、图片上传、识别结果、校验结果和分析汇总分开存储。

识别服务只向业务服务返回结构化结果；业务服务负责字段完整性、数学关系、置信度、图片指纹、订单号去重和 BD 历史归属校验。前端不直接写入业务数据。

## 错误处理与验收

- 主数据：错误 Excel 不覆盖现有版本；成功导入可回溯版本。
- 截图：失败图片不入库，提供明确失败原因；重复图片或订单不重复计入。
- 报表：时间、城市、BD、商家任一筛选变化均按上传时间重新计算；没有数据时显示零状态而非误导性图表。
- 验收样本：每个平台至少准备字段齐全、缺字段、金额异常、重复订单、BD 已变更五类截图，确认严格拦截和归属规则。

## 范围边界

第一版不提供普通账号、人工改数、人工补字段或第三方平台数据直连。后续如需增加自动采集、权限体系、更多平台或预警规则，应在本版数据模型稳定后单独规划。
