# P0-1 商家主数据导入设计

## 目标

让管理员把每日更新的合作商商家 Excel 导入 Cloudflare D1，并建立可查询的城市、商家和 BD 关联；本阶段不实现 BD 登录、图片上传、AI 识别、统计或导出。

## 已验证的数据源

文件：`商家数据源（每日更新）/合作商商家数据_明细数据-月_2026-07-01-2026-07-31(日期)_1785394157473.xlsx`。

- 工作表：`0`
- 数据行：13,577
- 必需列均无空值：`外卖组织结构`、`商家ID`、`商家名称`、`合作BD`
- 商家 ID 无重复；当前含 8 个城市/区县、81 位 BD。

## 导入字段映射

| Excel 列 | D1 字段 | 说明 |
| --- | --- | --- |
| 外卖组织结构 | City.name | 本阶段按“城市”统一命名，值可为城市或区县 |
| 商家ID | Merchant.merchantCode | 以文本处理，避免标识符精度或前导零问题 |
| 商家名称 | Merchant.name | 商家展示名称 |
| 合作BD | UserAccount.displayName / MerchantBdAssignment.bdUserId | 导入时建立或复用 BD 用户并建立归属 |

其余 Excel 列不会写入 D1；原始 Excel 也不会被系统修改。

## 同步规则

每次导入都是完整的最新商家名册：

1. 以 `(城市, 商家ID)` 作为商家唯一身份。
2. 已存在的商家更新名称；新商家新增。
3. BD 名称不存在时，创建活动中的 `BD` 用户；存在时复用该用户。
4. 对每个商家，关闭当前有效的不同 BD 关联，再创建或保留当前 BD 的有效关联；生效日为管理员填写的日期，未填写时使用导入当天。
5. 本次文件不存在的历史商家和历史关联不删除、不失效。这确保每日文件筛选范围变化时不会丢失历史数据；“下架/停用”逻辑不属于 P0-1。

## 校验与失败处理

导入接口先完整读取、规范化和校验全部行，再开启 D1 批量写入：

- 只接受 `.xlsx` / `.xls` 文件。
- 必需表头必须全部存在。
- 每行四个核心字段都必须非空。
- 同一文件内不能存在重复的 `(城市, 商家ID)`，也不能存在同一键对应不同商家名称或 BD 的冲突。
- 商家 ID 作为文本，禁止科学计数法或小数标识符。
- 任一校验失败时，接口不写入任何 D1 数据，并返回最多 20 条“行号 + 原因”。
- D1 写入异常时，接口返回失败，不显示成功统计。

## 管理员页面

`/admin/import` 保持单页流程：验证管理员口令 → 选择 Excel → 校验并导入。

成功后显示本次导入的总行数、新增商家、更新商家、新增 BD、更新关联、城市数，以及最近导入商家列表。列表包含城市、商家 ID、商家名称、负责 BD、关联生效日，并支持按城市、商家 ID/名称、BD 过滤。

## API 与边界

- `POST /api/admin/master-data`：支持 `verifyOnly=true` 的口令校验与实际文件导入。
- `GET /api/admin/master-data`：返回导入后的商家列表和筛选结果。
- 仅使用 Cloudflare D1 `DB` binding；不访问 PostgreSQL、CloudBase、Agnes 或 R2。
- 管理员口令继续通过 Cloudflare Secret `ADMIN_IMPORT_PASSCODE` 读取，永不返回给浏览器。

## 验收

1. 使用已验证的真实 Excel 进行线上导入。
2. 导入结果总行数为 13,577，且显示 8 个城市/区县和 81 位 BD。
3. D1 查询确认商家、BD 用户和商家-BD 关联真实写入。
4. 同一 Excel 第二次导入不会重复新增商家或 BD。
5. 缺少必需表头或包含重复商家键的测试文件被拒绝，且 D1 数据不变。
6. PC 与手机浏览器均能完成导入和查看列表。

## 非目标

不实现 BD 登录、BD 商家列表、订单图片上传、R2 存图、千问识别、人工确认、竞对计算、统计看板、导出和复杂权限。这些保留给 P0-2 及后续阶段。
